# Contributing

Read the repository README and its local contribution instructions before making a change. Repository-specific guidance takes precedence over these defaults.

For Nelcota's backend and SDKs, follow the [product contribution guide](https://github.com/Nelcota/Nelcota/blob/main/CONTRIBUTING.md) and [architecture decisions](https://github.com/Nelcota/Nelcota/blob/main/docs/decisions.md).

## Issues

Search existing issues first. For bugs, include the affected component, version, expected behavior, actual behavior, and a minimal reproduction. Remove credentials, tokens, personal data, and private URLs from logs.

Describe the problem and alternatives before proposing a substantial feature.

## Pull requests

Keep changes focused, explain the problem and resulting behavior, and include the checks that validate the change. Add meaningful tests for behavior changes and update documentation when needed. Use English for code, documentation, and commit messages.

Use [Conventional Commits](https://www.conventionalcommits.org/) where the repository follows that convention.

## Security

Report vulnerabilities privately as described in [SECURITY.md](SECURITY.md).
